# Карта проекта Detailing Studio

Проект — одностраничный русскоязычный лендинг на Next.js App Router, React и TypeScript. Главная страница находится на маршруте `/`; переходы между разделами выполняются по якорям. Исходники размещены в `src/`, алиас `@/*` соответствует `src/*`.

## Композиция страницы

`src/app/layout.tsx` задаёт `lang="ru"`, SEO-метаданные, шрифты Inter и Manrope через `next/font/google` и подключает `globals.css`.

`src/app/page.tsx` собирает страницу внутри `LeadProvider` в следующем порядке:

| Блок                              | Якорь             | Реализация                           |
| --------------------------------- | ----------------- | ------------------------------------ |
| Ссылка перехода к содержимому     | `#main`           | `page.tsx`                           |
| Шапка и мобильное меню            | Ссылки на разделы | `Header.tsx`                         |
| Главный экран со световыми лучами | `#home`           | `page.tsx`, `BeamsBackground`        |
| Преимущества с фоном из частиц    | `#advantages`     | `page.tsx`, `SparklesCore`, `Reveal` |
| Каталог услуг                     | `#services`       | `Services.tsx`                       |
| Примеры работ                     | `#portfolio`      | `Portfolio.tsx`                      |
| Описание студии и показатели      | `#about`          | `page.tsx`, данные `company.ts`      |
| Этапы работы                      | `#process`        | `page.tsx`                           |
| Отзывы                            | `#reviews`        | `Reviews.tsx`                        |
| Форма заявки                      | `#lead`           | `LeadForm.tsx`                       |
| Контакты                          | `#contacts`       | `page.tsx`, данные `company.ts`      |
| Подвал и мобильная кнопка заявки  | `#home`, `#lead`  | `page.tsx`, `MobileCTA`              |

Тексты преимуществ и этапов работы заданы массивами в `page.tsx`. Остальные основные наборы контента вынесены в `src/data/`.

## Связи и состояние

### Каталог и форма

`services.ts` → `Services` → `useLead().chooseService(id)` → `LeadProvider` → `LeadForm`.

`LeadProvider` хранит поля формы через `useReducer` и признак успешного заполнения через `useState`. Выбор услуги обновляет её идентификатор, сбрасывает успешное состояние и прокручивает страницу к `#lead`.

`LeadForm` использует `formatPhone` и `validateLead` из `src/lib/lead.ts`. При ошибке фокус переходит к первому невалидному полю. При успешной проверке данные сбрасываются, появляется подтверждение с фокусом и кнопкой повторного заполнения. Отправки на сервер и постоянного хранения данных в текущей реализации нет; API-маршруты и база данных отсутствуют.

### Навигация

`navigation.ts` → `Header` и подвал. `useActiveSection` отслеживает положение секций относительно шапки, события прокрутки, изменения размеров и якоря, возвращая идентификатор активного пункта. Мобильное меню реализовано через Radix Dialog. `MobileCTA` использует `IntersectionObserver` для отслеживания видимости формы.

### Галерея и отзывы

`Portfolio` читает `portfolio.ts` и локально хранит фильтр, состояние раскрытия и индекс открытого изображения. Radix Dialog обеспечивает просмотр фотографий; компонент добавляет переключение стрелками, свайпами и возврат фокуса к открывшей карточке.

`Reviews` читает `reviews.ts` и хранит состояние паузы. Движение ленты и её поведение при наведении, фокусе и уменьшении анимации описаны в `globals.css`. Дублирующая группа карточек нужна для непрерывного движения и скрыта от вспомогательных технологий.

### Общие визуальные компоненты

`Button` использует `class-variance-authority` для вариантов, Radix Slot для `asChild` и `cn()` для классов. `Reveal` использует Motion и учитывает настройку уменьшения анимации. `BeamsBackground` рисует лучи на canvas, а `SparklesCore` инициализирует tsParticles. Оба фоновых эффекта следят за видимостью и настройкой `prefers-reduced-motion`.

Файлы из `public/images/` доступны по URL `/images/<имя>.webp`. Каталог услуг и галерея формируют эти пути из имён изображений в данных; остальные иллюстрации подключаются непосредственно в компонентах через `next/image`.

## Проверки и конфигурация

| Команда             | Назначение и точка настройки                              |
| ------------------- | --------------------------------------------------------- |
| `npm run dev`       | Next.js в режиме разработки, привязка к `0.0.0.0`         |
| `npm run build`     | Production-сборка Next.js                                 |
| `npm start`         | Production-сервер, привязка к `0.0.0.0`                   |
| `npm run typecheck` | `tsc --noEmit`, параметры в `tsconfig.json`               |
| `npm run lint`      | ESLint, правила в `eslint.config.mjs`                     |
| `npm test`          | Vitest, конфигурация в `vitest.config.ts`                 |
| `npm run test:e2e`  | Playwright, конфигурация в `playwright.config.ts`         |
| `npm run format`    | Prettier для `src`, `tests` и корневых файлов TS/MJS/JSON |

Unit-тесты проверяют маску телефона, валидацию заявки, reducer и фильтрацию услуг. E2E-тесты покрывают навигацию, форму без передачи персональных данных, галерею, отзывы, мобильное меню, отсутствие горизонтального переполнения и декоративные эффекты при уменьшении анимации.

Playwright настроен на Chromium, Firefox и WebKit, использует `http://localhost:3000` и запускает `npm run start`, если сервер ещё не работает. Перед таким запуском нужна production-сборка. Трассировки сохраняются при ошибках.

## Служебные и генерируемые каталоги

Эти файлы и каталоги могут появляться локально и исключены из Git:

| Путь                 | Назначение                                                    |
| -------------------- | ------------------------------------------------------------- |
| `.next/`             | Результаты сборки, кеш и генерируемые типы Next.js            |
| `node_modules/`      | Установленные npm-зависимости                                 |
| `test-results/`      | Результаты и диагностические артефакты Playwright             |
| `playwright-report/` | HTML-отчёты Playwright при их генерации                       |
| `*.tsbuildinfo`      | Кеш инкрементальной проверки TypeScript                       |
| `.idea/`             | Локальные настройки IDE                                       |
| `.env*`              | Локальные переменные окружения; `.env.example` разрешён в Git |
| `*.log`, `.DS_Store` | Логи и служебные файлы macOS                                  |

`.git/` хранит историю и внутреннее состояние репозитория. Для работы текущей версии приложения переменные окружения не требуются.
